# Guess — 赛马竞猜投票平台

面向赛马爱好者圈子的竞猜投票网站。每场比赛每个用户只选一匹自己认为会赢的马，比赛结束后系统根据等级规则自动结算积分。

## 技术栈

- **前端**: Vue 3 + Vite + TypeScript + Vue Router 4 + Pinia + Axios
- **后端**: FastAPI + SQLAlchemy 2.0 (async) + Alembic + PostgreSQL 16
- **部署**: Docker Compose（VPS）

## 本地开发

### 前置条件

- Node.js 20+
- pnpm 9+
- Python 3.12+
- Docker & Docker Compose

### 启动步骤

```bash
# 1. 启动 PostgreSQL
docker compose up -d

# 2. 启动后端
cd backend
cp ../.env.example .env
# 创建并激活虚拟环境: python -m venv venv
# 安装依赖: pip install -r requirements.txt
uvicorn app.main:app --reload

# 3. 启动前端（新终端）
cd frontend
pnpm install
pnpm dev
```

### 访问

- 前端: http://localhost:5173
- API 文档: http://localhost:8000/docs
- 数据库: localhost:5432 (guess / guess_password)

### 导入历史得分

更新后端依赖后，在 `backend` 目录执行 `alembic upgrade head`，然后以管理员登录，从管理菜单进入“历史成绩”，或在排行榜页面选择“管理历史成绩”。工作簿需要包含“历史得分”和“赛事资料”工作表；历史得分表每行一个用户、每列一场比赛，导入前请为每行填写 QQ 号。

历史比赛独立于首页比赛保存，并按 QQ 与用户关联。非空得分（包括 0）计入总分和场次；赛事资料用于排行榜筛选，参赛马匹数为空时按 0 处理。与现有在线比赛同名同日期的记录会跳过。与已导入历史比赛同名同日期时，会对比赛资料及按 QQ 匹配的全部成绩进行比较：内容完全相同才自动跳过；存在差异则展示新旧值，必须逐场选择“保留已有内容”或“使用本次文件”。使用本次文件会替换整场历史比赛的资料和成绩，包括移除文件中缺少或为空的成绩。

导入选项“跳过完全相同的比赛记录”和“不导入无成绩的比赛”默认勾选。无成绩指 0 条得分记录，得分为 0 仍属有效成绩。取消前者会重新导入相同比赛（更新现有记录，不创建重复比赛）；取消后者允许导入空成绩比赛，若会替换已有成绩仍需核对差异并明确选择。修改选项会重新生成预览并清除旧的差异选择。

导入时，尚未注册的 QQ 会自动创建一个无法登录的占位用户，并生成绑定该 QQ 的未使用邀请码（在“用户管理”中显示为“占位·待注册”，不能删除）。把邀请码发给对应的人，对方用该 QQ 和邀请码注册时会直接接管占位用户，历史成绩无需迁移。撤销导入后若某个 QQ 已没有任何历史成绩，其占位用户会被删除，邀请码保留以便复用。

一个 QQ 只能对应一个账户：QQ 号必须是 5-20 位数字；已注册或已有未使用邀请码的 QQ 不能再生成邀请码。在“用户管理”中删除已绑定的邀请码，会同时删除该用户、其投票记录以及该 QQ 的全部历史成绩。

### QQ 头像

排行榜、Head to Head、投票分布和顶部导航会显示用户的 QQ 头像。头像由后端按 QQ 号从 QQ 头像服务获取并缓存，页面和图片地址中只出现不可逆的 `avatar_key`，不会暴露 QQ 号；获取失败时显示用户名首字。可通过环境变量 `QQ_AVATAR_URL` 修改头像地址模板（`{qq}` 为占位符）。

选择 Excel 后先预览新增、跳过的比赛及成绩数，再确认导入。格式错误会提示工作表行号或单元格位置。每次有效导入生成一个批次，可查看比赛和各用户成绩、修改整数得分；保存时会检查原分数，避免覆盖其他管理员的修改。撤销批次需再次确认，会删除本批次新增的历史比赛及成绩、恢复本批次更新前的完整快照，并保留撤销记录，不影响在线比赛、用户或马匹。若存在后续导入更新，需按从新到旧的顺序撤销；更新后又人工修分时，会阻止直接撤销以免覆盖新数据。请保留原始 Excel，以便需要时重新导入。

迁移 `017` 将既有历史比赛归入“既有历史成绩”批次，保留全部原始成绩。迁移 `018` 增加导入更新前后的快照记录，用于差异更新的撤销保护。

### 排行榜排序

排行榜默认按总分降序，可切换为按场均降序。场均排行仅保留参与场次达到当前筛选有效比赛数 60% 的选手，所需场次向上取整；分母与页面“当前结果包含”的比赛列表一致，包含在线及历史成绩，0分计为有效参与，不计空成绩或仅管理员参与的比赛。页面会以小字显示当前比赛数和最低所需参赛场数，总分排行不受该门槛限制。总分相同时按精确场均排序；场均相同时按总分排序。场均统一显示三位小数，排名按总分除以参与场数的精确值计算，避免显示舍入影响顺序。“距榜首”和“距上一名”随排序方式显示总分差或三位小数的场均差。排序兼容所有赛事筛选及历史成绩。

### Head to Head 对比

在排行榜点击“Head to Head 对比”，搜索并勾选至少两位用户，即可查看所有所选用户共同参与的比赛：每行一场、每列一位用户，并显示共同场次的得分合计。在线比赛仅纳入已结算且每个人都有得分的场次；历史成绩按 QQ 与已注册用户关联，未注册的历史用户也可选择。0 分和负分都是有效参与记录。

对比沿用排行榜已应用的日期、赛事标签、距离和马匹数筛选。用户列按选择顺序显示，手机上可横向滚动；用户或筛选变化时重新查询，忽略旧请求。未公开在线比赛继续遵循原有信息隐藏规则。
